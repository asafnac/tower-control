# העברת סנכרון, מצב לא־מקוון והתקנה למשחק אחר

מסמך זה נכתב כדי להדביק אותו בסשן שעובד על משחק ילדים אחר, כדי לתת לו את
היכולות שנבנו כאן ב־`asafnac/tower-control`. הקוד לשאוב נמצא ברפו הציבורי הזה.

---

## מה צריך להיבנות

ארבעה דברים, בסדר הזה:

1. **סנכרון בין מכשירים** — ילד אחד, שני מכשירים, בלי תלות בדפדפן
2. **מצב לא־מקוון** — המשחק עובד באוטו, בלי רשת
3. **התקנה למסך הבית** — אייקון ומסך מלא, בלחיצה אחת מתוך המשחק
4. **מסך הורים** — המקום שבו כל זה נשלט

---

## 1. הסנכרון

### הצורה

השרת הוא קופסה טיפשה עם מפתח סודי: מקבל שמירה, מחזיר שמירה. **כל התבונה בצד
הלקוח**, וספציפית בפונקציית מיזוג אחת. כל סנכרון הוא `קרא → מזג → כתוב`, ולכן
לא משנה מי סנכרן ראשון, מי היה מנותק שבוע, או אם אותו סנכרון רץ פעמיים.

### קבצים להעתקה כמו שהם

| קובץ | שינוי נדרש |
|---|---|
| `js/sync.js` | אין. תלוי רק ב־`PROGRESS.merge()` |
| `server/cloudflare/worker.js` | **כבר פרוס — לא צריך לפרוס שוב** |

השרת שומר לפי `sha256(code)`. משחק שני עם קוד שונה מקבל תא נפרד באותו KV,
בלי התנגשות ובלי הגדרה. **צריך רק לייצר קוד חדש לילד/ה.**

יש להוסיף את מקור המשחק החדש ל־`ALLOWED_ORIGINS` בוורקר (מערך מפורש של
origins). בלי זה הדפדפן יחסום את הבקשה ותקבל `Failed to fetch`.

### החלק היחיד שדורש חשיבה: המיזוג

זה הלב. `PROGRESS.merge(local, incoming)` חייב להיות:

- **חסין לסדר** — `merge(a,b)` ו־`merge(b,a)` נותנים אותו דבר
- **אידמפוטנטי** — מיזוג פעמיים לא משנה כלום
- **לא הרסני** — מכשיר ריק לא יכול למחוק מכשיר מלא

הכלל שעובד: **מקסימום ואיחוד.**

```js
merge(local, incoming) {
  const out = Object.assign(this._default(), local);
  const max   = k => { out[k] = Math.max(local[k] || 0, incoming[k] || 0); };
  const union = k => { out[k] = [...new Set([...(local[k]||[]), ...(incoming[k]||[])])]; };

  max('currentStage'); max('flightHours'); max('bestCombo'); max('streakDays');
  union('planesCollected'); union('stagesCompleted');

  // הלוג מאוחד לפי מפתח יציב שלא תלוי בשעון של אף מכשיר
  const seen = new Map();
  [...(local.log||[]), ...(incoming.log||[])]
    .forEach(r => seen.set(`${r.t}:${r.a}:${r.b}`, r));
  out.log = [...seen.values()].sort((x,y) => x.t - y.t);

  out.rank = this.getRankForStage(out.currentStage).name;
  return out;
}
```

**לכל שדה בשמירה של המשחק החדש צריך להחליט מה קורה כששני מכשירים חולקים.**
מילים שנלמדו → איחוד. רמה → מקסימום. שם → הלא־ריק. זו החלטה של חצי שעה מול
הקוד, ואסור לנחש אותה.

### שלוש מלכודות שעלו בפועל

**א. השדה שחייב להתקיים מהטעינה הראשונה.**
השרת דוחה גוף בלי `log` — הגנה שפויה מפני לקוח שבור שימחק שנה של היסטוריה.
אבל אם `_default()` לא כולל `log: []`, **הסנכרון הראשון ממכשיר חדש נכשל**
עם `not a game save`. השדה חייב להיות שם מההתחלה, ריק או לא.

**ב. הקוד הוא סוד ולא שייך לשמירה.**
הוא יושב במפתח localStorage נפרד (`<game>_sync`). השמירה היא מה שמייצאים
ומוסרים למישהו להסתכל עליו — קוד סנכרון בתוכה הוא סיסמה בקובץ שההורה חושב
שהוא דוח.

**ג. כפתור שלא אומר כלום נראה שבור.**
הגרסה הראשונה של "סנכרן עכשיו" עשתה `return` שקט כשהשדות לא נשמרו קודם.
ההורה לחץ, לא קרה כלום, והוא הניח שהמשחק שבור. **כל מסלול חייב להסתיים
במשפט בעברית** — כולל כשל. וכפתור "סנכרן" צריך לקחת את מה שעל המסך, לא לדרוש
"שמור" קודם.

### מה שהציל את היום

`SYNC.peek()` — קריאה בלבד שמראה מה יש בשרת, בלי לכתוב. מסך ההורים מציג:

```
כאן:     נמל 1 · 0 מטוסים · 0 תרגילים
בשרת:    אופיר · נמל 10 · 6 מטוסים · 300 תרגילים
ההתקדמות קיימת — לחץ "סנכרן עכשיו" והיא תרד למכשיר הזה.
```

בלי זה, הורה שפותח את המשחק במכשיר שהילד לא שיחק בו **לא יכול להבחין בין
"המכשיר הזה ריק" לבין "הכל נמחק"**. זה עלה לנו בערב שלם של בהלה. תבנה את זה
מההתחלה, לא אחרי.

## 2. מצב לא־מקוון

`sw.js` — להעתיק ולהחליף רק את רשימת קבצי המעטפת.

שתי אסטרטגיות שונות, וההפרדה חשובה:

- **מעטפת** (HTML/CSS/JS) — `network-first`. עדכון שנדחף מגיע מיד.
- **תוכן ממוען־תוכן** (קטעי קול בשם שהוא hash) — `cache-first, לנצח`. השם
  משתנה כשהתוכן משתנה, אז אין מה לפוג.

הקאש של התוכן **לא ממוספר בגרסה** בכוונה — פריסה חדשה לא זורקת 16 מגה שההורה
כבר הוריד.

**בדיקה שחייבת להיות בסוויטה:** כל `<script src>` ו־`<link rel=stylesheet>`
ב־`index.html` חייב להופיע ברשימת המעטפת של `sw.js`. קובץ שנוסף לדף ולא
ל־service worker עובד מצוין אונליין ופשוט נעדר באוטו. זו בדיקה של עשר שורות
עם regex והיא תופסת את זה בזמן build.

## 3. התקנה למסך הבית

הדפדפן מודיע מתי הוא מוכן להתקין, דרך `beforeinstallprompt`. תופסים אותו
**בזמן טעינה** — עד שההורה פותח את מסך ההורים האירוע מזמן חלף:

```js
window.addEventListener('beforeinstallprompt', e => {
  e.preventDefault();          // בלי זה כרום מציג באנר משלו
  OFFLINE._installEvent = e;
  if (typeof renderInstallButton === 'function') renderInstallButton();
});
```

האירוע **חד־פעמי**. לנקות אותו לפני ה־`await`, אחרת לחיצה שנייה זורקת.

צריך: `manifest.webmanifest` מקושר, אייקונים 192 + 512 (אחד `maskable`),
`display: fullscreen`, ו־service worker רשום. הכל חייב להיות מוגש ב־https.

למה בכלל כפתור בתוך המשחק: כרום קובר את "הוסף למסך הבית" עמוק בתפריט תחת שם
שמשתנה בין גרסאות, **ודפדפן פנימי של אפליקציה — מה שנפתח כשלוחצים על קישור
בוואטסאפ — לא מציע את זה בכלל.** הורה שעומד מול טאבלט לא אמור לחפש.

באייפון אין `beforeinstallprompt` בכלל. הכפתור נשאר מוסתר ובמקומו מוצגת שורה:
שיתוף ⬆️ ← "הוסף למסך הבית". באייפון זה גם **קריטי ולא קוסמטי** — ספארי מוחק
אחסון של אתרים שלא נכנסים אליהם שבוע, ואפליקציה במסך הבית פטורה מזה.

## 4. מסך ההורים

מאחורי **לחיצה ארוכה** (שנייה) על כפתור בפינה — לא נגיש לילד בטעות.

הכפתור חייב לסבול תזוזה של 16 פיקסלים באצבע. הגרסה הראשונה ביטלה את הלחיצה
ב־`mouseleave` והכשלה אחת מכל שמונה לחיצות בטאבלט.

מה יש שם:
- **קוד סנכרון** — כתובת + קוד + "צור קוד" + "שמור" + "סנכרן עכשיו" + ההשוואה
- **רמה נוכחית** — בורר שמזיז את הילד ישירות לרמה
- **הורדה ללא־מקוון** — כל קטעי הקול בבת אחת, עם פס התקדמות
- **התקנה** — הכפתור מסעיף 3
- **גיבוי / שחזור** — ייצוא JSON וייבוא שממזג

### בורר הרמה — למה הוא הכרחי

הבקשה המקורית הייתה "תמחק את השלבים הראשונים, שיתחיל משלב 8". זה היה הכלי
הלא נכון: הילד עדיין לא שולט בשלבים הנמוכים, ושלב 7 הוא הפיגום ששלב 8 נשען
עליו. **בורר שמזיז את הילד לרמה נותן את אותה תוצאה ולא לוקח כלום.**

```js
setStage(data, stageId) {
  const wanted = Math.round(Number(stageId));
  const to = Math.max(1, Math.min(this.maxStage(), Number.isFinite(wanted) ? wanted : 1));
  for (let i = 1; i < to; i++) {
    if (!data.stagesCompleted.includes(i)) data.stagesCompleted.push(i);
  }
  data.currentStage = to;
  data.currentStageShifts = 0;
  data.rank = this.getRankForStage(to).name;
  return data;
}
```

`0`, `-5`, `999`, `'nonsense'` ו־`7.6` חייבים כולם לנחות על רמה שקיימת. רמה
בלי שאלות היא מסך ריק לילד.

**להגיד להורה את האמת:** הורדת רמה היא מקומית בלבד, כי המיזוג תמיד שומר על
הגבוה. עדיף שידע ברגע שהוא עושה את זה מאשר שיגלה מחר.

## סדר עבודה מומלץ

1. לקרוא את השמירה של המשחק — אילו שדות יש, ומה המשמעות של כל אחד
2. **לכתוב את `merge()` ואת הבדיקות שלו לפני כל השאר** — זה הלב
3. להעתיק `sync.js`, להוסיף את המקור ל־`ALLOWED_ORIGINS` בוורקר
4. לבנות את מסך ההורים
5. `sw.js` + `manifest` + אייקונים + כפתור התקנה
6. לבדוק בדפדפן אמיתי, לא רק ביוניט: שני הקשרים, אחד ריק ואחד מלא, בשני
   הסדרים, ולוודא ששום צד לא נמחק

## מה לבדוק לפני שאומרים "עובד"

- מכשיר ריק שמסנכרן ראשון **לא מוחק** מכשיר מלא — בשני הסדרים, ופעמיים
- הסנכרון הראשון ממכשיר חדש לגמרי מצליח (מלכודת א')
- כל מסלול כשל בסנכרון מסתיים במשפט בעברית
- הדף עובד אחרי `Ctrl+Shift+R` ואז ניתוק רשת
- הכפתור התקנה: אין הצעה / ההצעה מגיעה כשהמסך פתוח / אישור / ביטול / כבר מותקן
